# Weekly Development Log

## Overview

This week marked one of the biggest milestones in the AI architecture so far.

The focus shifted from movement and navigation into **perception**, giving NPCs the ability to determine whether they can actually see the player before reacting.

Rather than building perception directly into the NPC class, a dedicated `VisionSystem` was introduced, continuing the modular architecture that has gradually emerged throughout the project.

---

# Major Features Completed

## VisionSystem

Created a dedicated `VisionSystem` responsible for NPC perception.

Current detection pipeline:

- Distance check
- Field of View angle calculation
- Raycast line-of-sight confirmation

The public interface remains intentionally simple:

```javascript
VisionSystem.canSee(observer, target)
```

Internally the system performs progressively more expensive tests while exposing a clean API to the rest of the engine.

This has become another reusable engine subsystem alongside:

- BulletSystem
- BlastSystem
- EnvironmentSystem
- NodeSystem
- WaypointManager
- DebugSystem

---

## HeadGroup Hierarchy

Refactored NPC hierarchy to introduce a dedicated `HeadGroup`.

Benefits include:

- Independent head rotation
- Vision direction attached directly to head movement
- Future support for looking at targets
- More believable NPC animation

The VisionSystem now naturally follows head movement without requiring additional logic.

---

## Raycast Visibility

Implemented the first version of raycast visibility testing.

NPC perception now follows a layered approach:

1. Distance
2. Viewing angle
3. Raycast confirmation

This provides realistic line-of-sight while keeping expensive raycasts to a minimum.

---

## Priority Waypoint Improvements

Completed implementation of priority waypoint support inside the `WaypointManager`.

NPCs now maintain:

- Base patrol waypoints
- Temporary priority waypoints

Once temporary objectives have completed, NPCs automatically resume their original patrol routes.

This creates much more believable behaviour without losing their underlying patrol logic.

---

## Debug Improvements

Early field-of-view cones proved useful during development but became visually overwhelming with larger numbers of NPCs.

The debug system was redesigned to use coloured status indicators above each NPC.

Current colours:

🟢 Patrol

🟠 Player detected within field of view

🔴 Target confirmed visible

This provides significantly clearer debugging while reducing screen clutter.

---

# Architectural Progress

The project continues to move toward a highly modular engine.

Current major systems include:

- EnvironmentSystem
- BulletSystem
- BlastSystem
- WaypointManager
- NodeSystem
- VisionSystem
- DebugSystem

Each system owns a single responsibility and communicates through simple interfaces rather than tightly coupled code.

This continues to make new features easier to integrate.

---

# Observations

One particularly satisfying milestone this week was reaching the point where perception became a complete pipeline rather than a collection of isolated features.

The NPC decision process now resembles:

Distance

↓

Angle

↓

Raycast

↓

canSee()

↓

Priority Waypoints

↓

Movement

Rather than scripting behaviour directly, independent systems are beginning to cooperate to produce AI behaviour.

This represents a significant architectural milestone for the project.
